# Colab 微調與 iPhone 學測例句生成

> 歷史研究紀錄：目前網站已改為內建教材與無語言模型的本機助手，先前 MiniLM／Danube 介面已撤下。現在的語音與操作方式請看 [本機語音](LOCAL_VOICE.md) 和 [最新驗證](BUILTIN_VALIDATION.md)。


目標是針對選定詞條，產生一個使用正確搭配、具有語境的原創英文例句。最新研究涵蓋 111–115 試卷與 115 起適用官方考試說明，用於分析風格與檢查近似抄錄；不把整份試卷當成訓練答案。AI 生成內容一律是自編練習，不代表官方試題、標準答案或已通過教師審核。請先讀 [五年再研究](GSAT_111_115_RESEARCH.md)，區分官方要求與網站短句練習設定。

## 交付內容

- `colab/gsat_danube_colab.ipynb`：可上傳 Google Colab 的筆記本，包含微調、合併、ONNX 量化、比較與匯出流程。
- `colab/gsat_workflow.py`：筆記本共用資料與評估邏輯。
- `colab/data/`：少量原創例句示範資料；不是足以證明模型品質的正式語料。
- `docs/GSAT_115_STYLE.md`：根據使用者上傳試卷建立的文法／風格分析。
- `docs/AI_RESEARCH.md`：研究來源、方法取捨與已驗證的支援範圍。
- 網站「學測例句生成」區：按需載入模型，在獨立 Worker 中推論，保留既有搜尋、收藏與學習功能。

## 在 Colab 執行

1. 將本機 `.ipynb` 上傳至 Colab，選擇 GPU 執行階段。這個雲端工作區沒有 GPU，也尚未完成 Danube 訓練。Colab 的 GPU 配額與種類由 Google 決定。
2. 依序執行儲存格，檢查模型的設定、授權、精確下載版本及實際 GPU。公開模型不應要求在程式中硬寫私人 token。
3. 示範資料只用來確認完整流程；正式用途先增加有權使用、教師審核的例句，涵蓋詞義、詞性、搭配、不同文法與情境。不要將未經確認的網路句子直接當正確答案。
4. 用 `target_word` 分組保留未見詞條作驗證／測試，避免同一目標字洩漏到不同切分。擴充語料後仍需檢查重複句與來源重疊。
5. 將 `UPLOAD_REFERENCE_PDF` 設為 `True`，可一次上傳五年試卷與官方說明，或其中一份，做近似抄錄檢查；依 SHA-256 去重並記錄來源。上傳子集不代表已檢查全部年份。官方說明中的歷年示例也參與比對，但不計為五年新試題。PDF、抽取文字及片段集合不進入訓練資料或匯出 ZIP。
6. 比較原模型、微調後模型與量化後模型：目標字命中、8–24 字、詞表涵蓋、過長／空輸出、近似抄錄及推論耗時。文法規則符合度與意思正確性仍需人工審核。
7. 合併 LoRA 後匯出具有 KV cache 的 ONNX，再產生 ORT MatMulNBits 4-bit。QLoRA 訓練用的 NF4 權重不能直接當作瀏覽器模型。
8. 下載候選模型壓縮包與評估報告。自動化指標通過不等於教師或手機驗證通過；不要以少量示範資料的結果宣稱「學測程度已保證」。

筆記本保留受支援且版本固定的套件組合；不在首次執行時任意升級全部套件。若 Colab Python／CUDA 基底改變，先核對套件相容性。ONNX 匯出可能需要 CPU RAM；不要同時保留原模型、訓練模型、合併模型與 ONNX session 而耗盡記憶體。

## 接到網站

網站不能直接使用原始 `h2oai/h2o-danube3-500m-chat` 的 PyTorch 權重。必須使用筆記本匯出的瀏覽器模型目錄，其中包含 tokenizer、設定、`runtime-manifest.json` 和 `onnx/model_q4.onnx`（及其外部權重檔）。

將匯出目錄放在支援 HTTPS、CORS 與大檔下載的公開模型主機。也可放在網站同源目錄，例如 `./models/gsat-danube/`。量化模型仍可能超過 GitHub 一般 Git 單檔 100 MB 限制；GitHub Pages 不會替你提供 GPU，也不要假設 Git LFS 大檔會變成可直接推論的 Pages 檔案。

網站設定接受模型公開 HF repo ID 或模型目錄網址，按「載入模型」後才開始下載。公開前端不應保存私人 Hugging Face token。私人模型若需登入，應另設有認證的後端；目前交付方案是本機推論。

manifest 版本 1 至少需要：`runtime: "transformers.js"`、`dtype: "q4"`、`device: "wasm"`、`max_input_tokens: 384`、`max_new_tokens: 96`，以及列出 `onnx/model_q4.onnx` 的 `model_files`。網站與筆記本使用同一份提示格式與輸入限制；修改訓練提示時應同步修改網站。

既有 MiniLM 是搜尋模型；Danube 是例句生成模型，兩者分開載入。在記憶體較小的手機上，先關閉不需要的分頁與模型，不要同時載入兩個模型做效能測試。停止功能會釋放 Worker，重新生成需再次載入。

## iPhone 13 實機驗收

在 HTTPS 網站、記錄實際 iOS／Safari 版本後，測試首次下載、第二次載入、詞條切換、8–24 字例句、停止／重試、背景切回與不同詞性。至少記錄下載大小、首次載入秒數、首個輸出時間、每句耗時、空輸出與錯誤率。選取冷門字、括號合併詞條與片語，確認目標字檢查沒有誤判。

Safari 26 / iOS 26 有 WebGPU 支援資訊，但裝置、驅動、算子與記憶體仍需實測。此方案先用不需要跨來源隔離的單執行緒 WASM；WebGPU 是後續評估選項。約 5 億參數的理想純 4-bit 權重約 250 MB，實際還包括未量化權重、tokenizer、KV cache、運算暫存與下載緩衝，不能把這個數字當成瀏覽器記憶體需求。

第一次載入需要網路；瀏覽器快取可能被 Safari 清除。本站沒有新增離線 service worker，因而不保證斷網後重新開站可用。完整 Danube 推論、微調效果、手機速度與記憶體安全，均須完成 GPU 及 iPhone 實測後才能宣稱。
