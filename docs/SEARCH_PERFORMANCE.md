## 已落實的方法

- **BM25 倒排索引。** 建立「詞項 → 詞條編號」表，BM25 只計算含查詢詞項的詞條。詞頻與文件長度沿用既有快取，避免複製一份詞頻。只出現於一筆詞條的詞項直接保存編號，有多筆才配置陣列，減少罕見中文詞塊的記憶體開銷。
- **拼字比較的有界運算。** 以三個重用的列陣列及距離帶取代每次配置完整矩陣，保留相鄰字母交換的 optimal string alignment 判定。超過搜尋容許距離的字串提早排除；不是把所有錯字距離近似成相同分數。
- **共用查詢前處理。** 每次搜尋只整理一次大小寫、查詢詞與英文判定。以精確詞條編號表查本機偏好，避免每筆偏好再掃整張詞表。
- **配合空閒時間暖建。** 檢查 `IdleDeadline.timeRemaining()` 和已用時間，每段以約 4 ms 為工程預算，剩餘時間不足即續排。逾期回呼至少處理一筆以保障進度；不支援 `requestIdleCallback` 時以 `setTimeout` 分段。維持單一待執行續排，完整建好後停止排程。

精確字、字族、片語、中文釋意、模糊拼字、概念擴展、三路 reciprocal-rank fusion、前 350 筆合併上限、穩定同分排序及本機偏好權重均沿用原規則。字面及概念查找仍會掃描詞表；倒排索引改善的是 BM25 這一路，沒有宣稱整個搜尋都變成常數時間。

空閒排程參照已直接讀取的 [W3C Cooperative Scheduling of Background Tasks 規範](https://github.com/w3c/requestidlecallback/blob/c4604781337b7bbfad37802a95f23907fca50e9e/index.html) 的 deadline、`timeRemaining` 及 timeout 章節。固定來源 SHA-256 為 `c33b119c8d5f83eac922ee656f16d9e07359b5edd82a0b9b42aa2363a79da9fe`。4 ms 是本站設定，不是 W3C 要求，也不保證某一筆超長詞條能在 4 ms 內建好。BM25 與倒排索引屬成熟檢索工程方法；這次沒有把它們寫成 2026 年新發明。

## 可重現的量測

```sh
node tools/benchmark_search.cjs --compare-ref 76bd5acc1e37bc112bd9187b7f823b611c26873f
node --test tests/search-performance.cjs
```

基準程式把同一份教材及共用程式快照交給兩個獨立 Node 程序，僅替換搜尋程式，避免先前 VM 的垃圾回收干擾記憶體差值。兩邊先建完整索引並暖執行 25 種查詢，再輪替順序執行 7 輪，共 175 筆**未使用結果快取**的查詢樣本。另量測已快取查詢的 1,000 次命中。程序使用 `--expose-gc`，索引堆增量是教材載入之後、索引建構前後的 `heapUsed` 差值；它不是整個頁面或瀏覽器的總記憶體。

本次 Node v24.19.0、6,019 筆詞條及 315 筆新編筆記的結果如下，完整數據見 [兩輪原始量測 JSON](data/search_benchmark_20261008.json)。保留驗證工作尚未結束時與結束後的兩輪，避免只挑延遲最低的一輪：

| 指標 | 驗證中：修改前 | 驗證中：修改後 | 驗證後：修改前 | 驗證後：修改後 |
| --- | ---: | ---: | ---: | ---: |
| 未快取查詢中位數 | 24.21 ms | 17.58 ms | 24.37 ms | 9.81 ms |
| 未快取查詢 P95 | 103.06 ms | 73.66 ms | 107.70 ms | 47.59 ms |
| 完整冷索引建構 | 561.67 ms | 845.00 ms | 591.68 ms | 665.16 ms |

| 1,000 次快取命中總時間 | 0.79 ms | 0.96 ms | 0.76 ms | 0.82 ms |

驗證後這輪中位數下降約 60%，P95 下降約 56%；驗證中那輪分別下降約 27%、29%。兩輪索引均多用約 12.50 MiB，冷建構增加約 73–283 ms。快取命中總時間差不足 1 ms，沒有據此宣稱快取速度改善。

每一輪的修改前後都使用完全相同的教材快照；**兩輪之間**的合成快照雜湊不同，原始 JSON 各保留 `materialSha256`，因為編寫中的資料其間仍有修訂。因此跨輪差異不能全歸因於系統負載。測量也受硬體、引擎和教材量影響，不能據此保證手機瀏覽器的延遲或省電效果。

首次搜尋若發生在空閒暖建尚未完成時，仍同步補完索引，以免漏掉後段詞條；因此**完整冷建構仍可能阻塞主執行緒**。這次量測的查詢延遲是索引已完成之後，不包括 HTML 解析、DOM 呈現或網路載入。若將來採用 Web Worker 或預建索引，需另測初次查詢、通訊成本、容量與結果一致性，不能沿用這份成績。

## 結果一致性驗證

`tests/search-performance.cjs` 使用獨立的完整矩陣參考算法，對長度 0–4 的所有 `a/b/c` 字串配對及真實詞的刪字、插字、代換、交換測試距離 1、2 的門檻；再把倒排搜尋與保留的整表 BM25／融合實作逐筆比對，檢查分數、順序、命中理由、通道及本機偏好。包含部分暖建後的冷查詢，以及編號 0 的單筆倒排項目，防止漏筆與重複建構。

另外用可控時鐘確認已用預算、逾期 deadline、單一續排和 `setTimeout` 備援。這四項測試目前全部通過。搜尋品質是結果一致性的範圍；教學成效、記憶提升或學測分數沒有由這些工程測試驗證。
